# 归档、查重与写后验证

## 目标与证据

沿用配置的目标层级，例如 `Meeting / YYYY-MM-DD / 主题`；现有结构与 URL 优先。每个日期维护中央工作日志和导航，会议内维护对应“当天执行日志”并互链。实时读目标和源链接后再创建；本机 state 只是缓存与恢复线索。

记录建议包含：

```markdown
时间：<本地日期、起止、时区>
来源：<Wispr 返回的链接或来源 ID>；原文覆盖：<完整/待补>
一句话结论：<本场带来的变化>

关键事实：<少量有证据的要点>
已确认决定：<决定、确认人/时间、适用范围、证据>
提议与 thoughts：<来源归属、尚需验证的假设>
行动：<结果、明确负责人或待确认、期限或待确认、依赖>
待确认：<范围、分工、取舍、缺失证据>
当天执行日志：<本次增量与中央日志链接>
```

不要每次追加一整份新摘要。先更新最新有效摘要和关联行动，保留被替代记录的时间与原因；已确认原文、人工评论、附件、图片、Mermaid 和文档权限都保留。写回只涉及本次证据支持的内容，不能假称已重读 Slack/GitHub/Linear/Research。

## 去重与多人归档

先匹配 provider + source ID / share link，再核对实际 occurrence 的起止时间、主题与参与者。人工粘贴过的会议也应复用既有档案。标题相近或同一 recurring meeting 不是同一场次；不确定就保留候选，避免合并不同会议。

不同成员的 Wispr 账号可能给同一场次返回不同 source ID。私有状态应区分来源账号，以共享档案中的 occurrence、来源链接和实际内容核对。既有共享 registry/锁可用时沿用；没有时在写入前重新读取目标，写后再查重复。两个私有本地状态不能提供跨机器 exactly-once 保证；发生冲突时停下该目标并保留两方证据，不覆盖对方编辑。

## 私有恢复状态

沿用既有 schema，不重置他人的 state。新环境至少记录：

- 本次扫描范围、来源发生/修改时间、来源 ID、内容哈希、完整性与读取覆盖。
- canonical occurrence 与目标 URL/ID 映射。
- 每个目标的 revision/hash、pending/written/verified、最近验证时间、待处理原因。
- 若明确授权发送消息，单独记录收件人、消息链接、hash 与发送状态；不让 docs 成功代替消息成功。

先保存草稿和 pending，再逐目标写入。重新加载并核对实际关键句、源链接、层级及相关图表后才更新该目标 verified。源的最终成功 checkpoint 必须等全部必需目标完成；允许记录 partial observation 供重试，不能凭它跳过失败目标。来源随后有新内容时重新打开对应目标。

写入响应不明时，先读目标寻找这次 revision/内容，再决定是否重试。一次编辑失败可在重新读取后重试一次；再次失败就保留 pending 和草稿，交付已完成部分。不要覆盖整个旧 state 文件或无限重放同一写入。

## docs 浏览器写回

优先使用目标系统的受支持文档能力；若项目指定内置浏览器，就按该设置，不切换成员正在使用的原生浏览器。没有访问权限时保留草稿，只请求所缺登录。

对于 Outline 富文本编辑器，以下做法来自实际操作：

- 先读取当前目标，保存私有备份；优先在明确段落局部编辑，避免全篇替换损坏人工内容。
- 复用现有富文本时，通过编辑器复制得到的规范 HTML 保留代码块和 Mermaid；页面 DOM 可能混入按钮、锚点和 React 控件，不能原样重新粘贴。
- 需要富文本粘贴时剪贴板只放 `text/html`；同时放 plain text 的客户端可能优先插入纯文本。精确定位段落后粘贴，并检查标题没有误留在列表项内。
- 标题自动保存可能晚于输入结束；等待保存状态完成或执行其他读取后再 reload。立即 reload 会丢失新标题。
- 按当前客户端提供的受支持 UI API 操作；页面 evaluate 只读 DOM，不调用隐藏接口或注入编辑器内部状态。

以上是条件性操作提示，不能替代实际 reload/readback；客户端能力不同则采用它支持的方式。
